Step by step

Anatomy of the attack

1

User logs into bank.com

Browser stores Cookie: session=abc123. This cookie will be sent with every future request to bank.com.

2

User visits evil.com in another tab

A meme site, phishing link, or any page the attacker controls. The bank tab stays open — session is still active.

3

evil.com contains a hidden form

<form action="bank.com/transfer" method="POST"> with attacker-chosen values. A script auto-submits it on page load.

4

Browser sends the POST — with cookies attached

The request goes to bank.com, so the browser automatically includes bank.com's session cookie. This is browser behavior by design.

5

Bank processes the forged request

Valid session cookie → valid user. The bank can't distinguish this from a real transfer. The user never clicked anything.

Defense layers

How to stop CSRF

Each layer catches what the one above misses. Stack them.

L1

SameSite=Lax cookies

Browser won't send cookies on cross-site form POSTs, fetch, or iframes. Default in modern browsers — zero code needed.

Set-Cookie: session=abc; SameSite=Lax; Secure; HttpOnly
STOPS ~90% OF CSRF
L2

CSRF tokens

Server embeds a random token in each form. Attacker can't read it (Same-Origin Policy) so they can't forge a valid submission.

<input type="hidden" name="_csrf" value="random-xyz">
CATCHES THE REST
L3

Origin / Referer validation

Server checks the Origin header — a cross-site request reveals the attacker's domain. Fallback to Referer.

if (origin !== 'https://bank.com') reject()
DEFENSE IN DEPTH
L4

Re-authentication

For critical actions, require the user to enter their password again. Attacker can trigger the request but can't supply credentials.

Attack surface

Common attack vectors

Hidden form auto-submit

POST

Page with a hidden form that auto-submits on load via onload. The classic CSRF payload.

Needs JS Blocked by Lax

Image tag GET

GET

An <img src="bank.com/do?..."> triggers a GET with cookies. Works in emails and forums — no JS needed.

No JS Bypasses Lax

JSON body trick

POST

Form with enctype="text/plain" crafts a valid JSON body. Works if the server doesn't check Content-Type.

Needs JS Blocked by Lax

Login CSRF

POST

Logs victim into the attacker's account. Victim enters personal data — it's saved to the attacker's profile.

Often unprotected Blocked by Lax

Clickjacking combo

ANY

Hidden iframe over a decoy button. User "voluntarily" clicks the real action. Bypasses some token defenses.

No JS Blocked by X-Frame-Options

Stored CSRF

GET

Injected <img> in a forum post fires for every viewer. Mass exploitation from a single payload.

No JS Bypasses Lax
